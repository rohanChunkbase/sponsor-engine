# Safety

Test mode is the default.
`DRY_RUN` is `true` until you set it to `false`, `0`, or `no`.
The dashboard shows a Test mode badge on every page.

This repository has no email sender.
This repository has no WhatsApp sender.
This repository has no payment method.
This repository has no food-order account.

<Warning>WARNING: Do not set DRY_RUN to false until you want a row marked sent. A marked send is still not a delivered email. This build has no mail service.</Warning>

## Outbox states

The outbox has five states.

- `draft`
- `awaiting_approval`
- `approved`
- `sent`
- `blocked`

`send_with_approval` does not send.
It writes a row with status `awaiting_approval`.
`draft` is a legal state.
The send tool does not start in `draft`.

A person presses **Approve**.
That action moves the row from `awaiting_approval` to `approved`.
In test mode, Approve writes a log.
The row does not move to `sent`.

A person can press **Edit** while the row is `draft` or `awaiting_approval`.
Edit changes the text.
Edit does not change the state.

A person can press **Skip** while the row is `draft` or `awaiting_approval`.
Skip moves the row to `blocked`.
The note is "A person skipped this."

The row moves to `sent` only when all of these are true.

1. The status is `approved`.
2. `DRY_RUN` is `false`.
3. The recipient is in `ALLOWLIST`.

When `DRY_RUN` is `false` and the address is not on the allow list, the row moves to `blocked`.
The note is "The address is not on the allow list."

A test checks that a row cannot reach `sent` before approval.
`sent` and `blocked` have no next state.

## Allow list

`ALLOWLIST` is a comma-separated list of addresses.
The check uses lower case.
An empty list blocks every address when test mode is off.

1. Keep `DRY_RUN` set to `true` while you test.
2. Add one test address to `ALLOWLIST` when you leave test mode.
3. Press Approve on that one row.
4. Read the audit row.

The dashboard stores the decision in the approvals table.
The run log stores the tool name and a short summary.

## What Approve does with a CRM

Approve calls `pushDeal` when `packages/integrations` is present.
When that package is absent, the result says the built-in list still holds the deal.
A failed CRM call does not delete the outbox row.
