The server name is `sponsor-engine`.
The version is `0.1.0`.
Each section comes from `packages/mcp/src/server.ts`.
The script `apps/site/scripts/extract-tools.mjs` writes this page.
The script stops when a tool has no example.
The script stops when an example field is not in the schema.

Ids in the examples are samples.
A live call makes its own ids.
Room prices in the quote example use the SAMPLE history.
Do not use SAMPLE prices for a real venue.
The forecast example uses the benchmark path.
The benchmark path runs when fewer than three past bookings of that kind exist.

Read [Safety](/safety) before you change `DRY_RUN`.

## triage_inbound

Read an inbound message.

Read a chat message. Record who is asking, whether they are a community or a company, the date, the headcount, and what they need. Create a task with an owner and a priority. Log a failure when the message cannot be read. The reply waits for a person.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `message` | `string` | Yes | The chat message |
| `channel` | `string` | No | whatsapp, email, or web |
| `sender_name` | `string` | No | The server stores this value. |

### Example call

```json
{
  "name": "triage_inbound",
  "arguments": {
    "message": "This is Amina from Thames Agent Builders. Can we book an evening hack for 80 people on 12 November 2026? We need food.",
    "channel": "whatsapp",
    "sender_name": "Amina"
  }
}
```

### Example result

```json
{
  "ok": true,
  "qualified": {
    "sender_name": "Amina",
    "organisation": "Thames Agent Builders",
    "requester_kind": "community",
    "event_date": "2026-11-12",
    "headcount": 80,
    "needs": [
      "food",
      "evening"
    ],
    "venue_hint": null,
    "owner": "Venue lead",
    "priority": "p1"
  },
  "task": {
    "title": "Book Thames Agent Builders — 80 people",
    "owner": "Venue lead",
    "priority": "p1",
    "status": "open"
  },
  "outbox": {
    "status": "awaiting_approval",
    "kind": "chat_reply"
  },
  "suggested_reply": "Thanks Amina. I have this as a community booking for Thames Agent Builders on 12 November 2026 for 80 people. You asked for food, evening. A person here will confirm the price before anyone replies."
}
```

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |

| `headcount` | `number` | No | The server stores this value. |
| `date` | `string` | No | The server stores this value. |
| `community_name` | `string` | No | The server stores this value. |

## find_sponsors

Find sponsors.

Rank sponsors for an event from past London backing, food or venue fit, and size. Return reasons and source URLs. Calls companySize and lumaEventHosts when packages/integrations is present.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `request_id` | `string` | No | The server stores this value. |
| `community` | `string` | No | The server stores this value. |
| `headcount` | `number` | No | The server stores this value. |
| `needs` | `string[]` | No | The server stores this value. |
| `focus` | `string` | No | The server stores this value. |
| `limit` | `number` | No | The server stores this value. |
| `include_sample` | `boolean` | No | The server stores this value. |

### Example call

```json
{
  "name": "find_sponsors",
  "arguments": {
    "community": "Encode Club",
    "headcount": 80,
    "needs": [
      "food"
    ],
    "focus": "ai",
    "limit": 3,
    "include_sample": false
  }
}
```

### Example result

```json
{
  "live_note": "Live lookup is off. These matches use the London sponsor list on this computer.",
  "matches": [
    {
      "company": "Anthropic",
      "website": "anthropic.com",
      "category": "AI lab",
      "london_events": 6,
      "food_or_drinks_events": 1,
      "reasons": [
        "Anthropic is named as paying for food or drinks at 2 London events. One page says: “We will provide food and drink, thanks to Anthropic!”"
      ],
      "sources": [
        {
          "url": "https://luma.com/4z45zkng",
          "quote": "We will provide food and drink, thanks to Anthropic!",
          "role": "food",
          "confidence": "stated",
          "event_name": "Claude Code Meetup London",
          "community": "Claude Community Events"
        }
      ]
    }
  ],
  "note": "A live call also returns sponsor_id, score, venue_events, and is_sample. The rank uses the London list on this computer."
}
```

## forecast_turnout

Forecast turnout.

Estimate how many people will come. Uses this community's history when it has at least three events. Otherwise uses the free-event no-show benchmark of 28%.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `headcount` | `number` | Yes | The server stores this value. |
| `requester_kind` | `community | company | unknown` | No | The server stores this value. |
| `community_name` | `string` | No | The server stores this value. |
| `request_id` | `string` | No | The server stores this value. |

### Example call

```json
{
  "name": "forecast_turnout",
  "arguments": {
    "headcount": 80,
    "requester_kind": "community",
    "community_name": "A new community"
  }
}
```

### Example result

```json
{
  "headcount": 80,
  "expected_heads": 58,
  "show_up_rate": 0.72,
  "no_show_rate": 0.28,
  "source": "benchmark",
  "history_events": 0,
  "community_name": "A new community",
  "benchmark": {
    "no_show_rate": 0.28,
    "show_up_rate": 0.72,
    "note": "Free events with no history use a 28% no-show. Show-up is 72%."
  },
  "summary": "There are fewer than three past events for this requester. We use the free-event benchmark: a 28% no-show, so 72% show-up. We expect 58 of 80 people.",
  "note": "This is the benchmark path. The benchmark runs when the database has fewer than three past bookings of this kind. Three or more bookings use the median show-up from that history."
}
```

## draft_sponsor_ask

Draft a sponsor email.

Draft a right-sized sponsor ask from the turnout forecast, about £5.50 per person for food. Put the email in the outbox. Do not send it.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `request_id` | `string` | No | The server stores this value. |
| `sponsor_id` | `string` | No | The server stores this value. |
| `sponsor_name` | `string` | No | The server stores this value. |
| `headcount` | `number` | No | The server stores this value. |
| `community` | `string` | No | The server stores this value. |

### Example call

```json
{
  "name": "draft_sponsor_ask",
  "arguments": {
    "headcount": 80,
    "community": "A new community"
  }
}
```

### Example result

```json
{
  "ask_gbp": 319,
  "per_head_gbp": 5.5,
  "expected_heads": 58,
  "show_up_rate": 0.72,
  "sent": false,
  "outbox": {
    "status": "awaiting_approval",
    "kind": "sponsor_email"
  },
  "note": "The ask is the food cost. It is £5.50 for each person the forecast expects. The email waits in the outbox. The tool does not send it."
}
```

## send_with_approval

Queue a message for approval.

Never sends. Writes the message to the outbox with status awaiting_approval.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `recipient` | `string` | Yes | The server stores this value. |
| `subject` | `string` | Yes | The server stores this value. |
| `body` | `string` | Yes | The server stores this value. |
| `kind` | `string` | No | The server stores this value. |
| `request_id` | `string` | No | The server stores this value. |
| `sponsor_id` | `string` | No | The server stores this value. |
| `sponsor_name` | `string` | No | The server stores this value. |
| `ask_gbp` | `number` | No | The server stores this value. |

### Example call

```json
{
  "name": "send_with_approval",
  "arguments": {
    "recipient": "partnerships@example.com",
    "subject": "Food for an 80-person community evening",
    "body": "Hello, we are asking for the food cost. A person must approve this before it can be sent.",
    "kind": "sponsor_email",
    "ask_gbp": 319
  }
}
```

### Example result

```json
{
  "sent": false,
  "reason": "Waiting for a person. Nothing was sent.",
  "item": {
    "status": "awaiting_approval",
    "kind": "sponsor_email",
    "recipient": "partnerships@example.com",
    "subject": "Food for an 80-person community evening",
    "ask_gbp": 319
  }
}
```

## approve

Approve a waiting message.

Move an outbox item to approved. In test mode this only logs and does not send. Calls pushDeal when packages/integrations is present.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `outbox_id` | `string` | Yes | The server stores this value. |
| `actor` | `string` | No | The server stores this value. |

### Example call

```json
{
  "name": "approve",
  "arguments": {
    "outbox_id": "out_example",
    "actor": "organiser"
  }
}
```

### Example result

```json
{
  "sent": false,
  "reason": "Approved. Test mode is on, so nothing was sent.",
  "deal": {
    "used": "built-in"
  },
  "item": {
    "id": "out_example",
    "status": "approved"
  },
  "note": "Test mode is the default. Approve writes a log. The row stays approved. The row moves to sent only when DRY_RUN is false and the recipient is on the allow list."
}
```

## recall_history

Recall history.

Look up past events, bookings, and sponsor notes. Uses Cognee recall when packages/integrations is present. Uses the local database otherwise.

### Input

| Field | Type | Required | Purpose |
| --- | --- | --- | --- |
| `query` | `string` | Yes | The server stores this value. |

### Example call

```json
{
  "name": "recall_history",
  "arguments": {
    "query": "Anthropic"
  }
}
```

### Example result

```json
{
  "source": "local",
  "external": null,
  "events": [],
  "claims": [
    {
      "company": "Anthropic",
      "evidence_quote": "We will provide food and drink, thanks to Anthropic!",
      "source_url": "https://luma.com/4z45zkng",
      "event_name": "Claude Code Meetup London"
    }
  ],
  "bookings": [],
  "note": "Cognee is not connected. This answer uses the bookings and sponsor notes on this computer."
}
```
